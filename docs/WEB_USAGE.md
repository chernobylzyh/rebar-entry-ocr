# 网页启动、审核与导出

首次使用从 [README](../README.md) 安装；阶段细节见 [完整流程](WORKFLOW.md)。以下命令在仓库根目录运行。

## 启动和停止

使用现有 conda 环境 `ocr`：

```bash
conda activate ocr
python -m pip install -e .
python -m material_ocr serve --port 8080 --data-dir runs/web \
  --model-cache models/paddlex_cache --review-library runs
```

安装只在首次使用或依赖变化时执行。出现 `Uvicorn running on http://127.0.0.1:8080` 后打开 [http://localhost:8080](http://localhost:8080)。保持终端运行；WSL 环境可在本机 Windows 浏览器访问该地址。CPU 环境启动增加 `--device cpu --profile complete`。

终端按 `Ctrl+C` 停止。刷新网页不会重新执行 OCR；再次启动载入已完成任务，未完成任务记为中断，尚不支持跨服务自动续跑。

人工审核保存于自己的浏览器。继续查看原确认时使用相同地址和浏览器；协议、主机名、端口或浏览器改变，会读到不同的浏览器缓存。

## 新 PDF / 文件夹

1. 材料选「钢筋」，版式选「自动选择支持的版式」。钢梁、混凝土显示待接入。
2. 「选择文件」可多选 PDF；「选择文件夹」读取目录和子目录的 PDF，推荐 Chrome / Edge；也可拖入 PDF。
3. 检查列表后点击「开始识别与匹配」。每批最多 100 份、单份最多 256 MB、整批最多 1 GB。
4. 查看任务的页数与阶段进度。检验表阶段和附件阶段使用独立进程，各 PDF 独立匹配、顺序执行。
5. 完成后点击「查看匹配与审核」；「检验记录原图」检查逐页路由与提取，「材料统计」查看带单位和重复说明的统计，「运行日志」排查失败。

相同文件、材料、规则、代码及运行选项已有完整结果时复用并说明来源。复杂页面仍可能耗时；GPU、batch 和进程隔离不代表每份 PDF 已有统一的加速倍数。

## 找已有结果

首页任务卡选择「已完成」的对应 PDF，点击「查看匹配与审核」。同名失败任务保留日志，可继续排错。

启动参数 `--review-library runs` 使首页「已有审核结果」发现已有 `*/review/index.html`，按 PDF 展示最新版。原任务入口也会指向同 PDF 最新回放，查看不会重新 OCR。新克隆仓库没有业务产物，只有另行迁移了 `runs/` 才会看到这些结果。

修改服务代码后重启服务。审核 HTML 与 JS 是结果生成时的静态副本；需要更新旧页面的规则或交互时，用保存证据 `replay` 到新目录。

## 人工确认四表

1. 默认筛选「待补全 / 待复核」。唯一且无待核验项的四表自动捆绑，可切到「已捆绑记录」查看。
2. 查看三类完整候选：质量证明书、铭牌、送货单。分类成功但缺编号 / 炉号的页面仍可选；核对原图、字段和冲突说明。
3. 选择三类表单，填写核验结论，点击「人工确认并捆绑四表」。同页多铭牌按独立炉号及实体区分，送货单按物理行选择。
4. 本次确认同步重复检验来源，并扣除已用铭牌 / 送货行，缩小后续候选。质量证明书覆盖多个物料时，核验后勾选允许共用；「查看已捆绑表单」可检查完整库存。
5. 可「解除本组捆绑」，将附件还回候选池。点击「下载捆绑与审核结果」保存 JSON，或「下载捆绑清单 CSV」取得当前关联清单。

人工状态保存于原浏览器缓存。清理缓存或迁移前下载 JSON；在同 PDF 的审核页「导入审核 JSON」恢复。服务器 `review_states/` 保存不可变备份，但页面不会自动从这些文件恢复。原始 OCR 和磁盘自动匹配 CSV 不随人工操作覆盖。

## 台账字段审核与导出

1. 已捆绑物料显示于下方「自动填表 · 材料报审台账」，点击「更新台账预览」。
2. 点击对应行，选择报审信息来源，打开报审表、铭牌、送货单和质证书原图。
3. 核对材料名称、规格品种、生产单位、供应单位、供货日期、使用部位、炉批号、验收数量、质保书编号及可空文件编号。重量取关联送货物理行，单位为 t。
4. 字段存在多个 OCR 值时显示「字段候选冲突」，可选候选或按原图补正并备注；点击「确认本行字段」。
5. 点击「导出已确认行 Excel」，下载包含「材料台账」「字段溯源」的 XLSX。默认仅导出有效且已确认行，剩余未确认和待匹配数量继续提示。

四表匹配确认不等于字段确认。改选、解除关联或字段提取版本变化会使旧确认失效；服务端导出前重新检查。一个独立铭牌对应一行，重复检验来源保留引用。遮挡无法确认的字段留待补正。

「下载捆绑清单 CSV」导出页码 / 编号观察 / 送货行等四表关联，正式十列台账当前只有 XLSX 导出。需要台账 CSV 时，在 Excel 中将「材料台账」另存为 UTF-8 CSV；字段溯源需单独保留。各导出的准确字段见 [流程说明](WORKFLOW.md#8-下载-csv审核-json-和-excel)。

## 接收方核验

新克隆不包含开发者的业务 PDF、运行结果和浏览器记录。上传自己的样本，从任务卡打开结果，按 [运行与核验说明](ACCEPTANCE.md) 检查分类、匹配、候选库存、台账与导出，并在自己本地保存核验结论。

## 常见问题

|现象|定位 / 操作|
|---|---|
|浏览器连接失败|确认终端服务仍在运行，地址和启动端口一致|
|端口已占用|打开现有服务；另开端口会拥有独立浏览器审核缓存|
|缺 `material_ocr` 或依赖|激活 `ocr`，在根目录执行 `python -m pip install -e '.[test]'`|
|未找到检验记录页|查看逐页分类；标题、方向或版式可能未通过路由|
|已找到检验页但提取失败|查看检验页原图和几何 / 单元格诊断，与分类未找到区分|
|质证编号或铭牌缺失|依次查页角色、原文 OCR、字段提取；从完整候选人工核对|
|规则改了结果仍旧|重启服务，基于同 PDF 保存证据回放生成新版审核目录|
|新浏览器没有人工记录|回到原地址 / 浏览器，或导入已下载的审核 JSON|
|台账导出不可用|从工作台打开新版审核页，完成捆绑及逐行字段确认|
|任务中断 / 失败|看运行日志，旧产物保留；处理原因后重新上传，不自动跨服务续跑|

网页任务保存在 `runs/web/job-*/`，文件审核页在 `documents/file-*/review/`，导出在 `review/exports/`。目录职责见 [代码地图](CODE_MAP.md)，提交范围见 [GitHub 说明](GITHUB_SUBMISSION.md)。

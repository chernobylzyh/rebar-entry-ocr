# 从 PDF 上传到台账核验和导出

当前钢筋流程由 Vue、Java 和 Python 三部分组成。启动命令见 [README](../README.md)，字段与接口约定见 [自动台账说明](AUTOMATIC_LEDGER.md)。

## 服务分工

|组件|默认端口|职责|
|---|---|---|
|Vue|5173|上传、历史记录、原图和位置框、台账补正、最终核验与下载|
|Java|8080|业务接口、历史持久化、文件管理、补正和核验、导出|
|Python|8000|PDF 渲染、本地 OCR、独立铭牌提取、自动匹配和原始证据|

Vue 访问 Java；Java 调用 Python。Python 返回原始 JSON，Java 的业务响应包装为 `{code,data,msg}`。本地 Java 使用 H2，MySQL 是可选部署配置。

## 1. 上传与渲染

Java 接收 PDF 并调用 Python 渲染页面，保存业务历史和页面文件。上传成功后可查看原图；此时不代表 OCR 或台账已生成。同名覆盖、重新切分和清缓存会按各自操作范围使已有结果失效。

## 2. 提取与证据

Python 对进场记录、报审表及附件进行分类和 OCR。进场表提取保留记录、字段来源和失败诊断；数量清单可按空间结构补充进场记录。

多张铭牌先划分物理区域，再分别 OCR 并保留独立 ID。全页文字可作证据，但不把多张铭牌的牌号、直径、炉批号和公司名称混成一个字段池。证据保留页码、原文、坐标与像素尺寸；没有可靠坐标时不虚构位置框。

## 3. 自动匹配

存在质证编号时按编号定位质证书，再依据炉批号关联铭牌，利用规格和数量关联送货物理行。缺少质证编号时，同一铭牌内的牌号与直径必须同时匹配，再关联送货行和质证书。

同页或相邻页不能单独证明关联。数量仅在规格条件满足的候选中辅助消歧。不同独立铭牌保留各自 ID；同一铭牌被多条进场记录使用时保留重复或冲突提示，重复进场记录不累加数量。

每条进场记录进入最终台账；缺失、矛盾或歧义保持可见，匹配不完整不会转入中途人工捆绑。编号和炉批号不凭猜测改写。

## 4. 最终台账

当前台账采用 12 列：供应商是否报审、文件编号、材料名称、规格品种、生产单位、供应单位、供货日期与工程材料报审签认日期、使用部位、送货单编号、炉批号、验收数量、质保书编号。

没有可靠来源的字段留空并提示。数量统一为吨，保留取值来源及数量差异。前端点击字段或诊断查看证据，双击单元格补正；补正保留原始 OCR 观察和来源。

## 5. 核验与导出

用户集中检查关键字段及全部异常后确认当前台账版本。Java 校验关键必填字段与版本；缺失必填项或版本变化时拒绝确认。字段修改或重新识别使原确认失效。

导出前再次检查核验状态。Excel 包含台账和字段溯源；总台账导出也检查所涉及各卷的核验状态。来源链完整只说明关联状态，不能代替字段准确性核验。

## 本地数据与交付

Python 运行目录 `runs/web/library/` 保存 PDF、页面、OCR 索引和自动匹配结果；Java 的 `前端/image/library/` 保存业务文件和核验相关数据；H2 文件位于 `前端/runtime/h2/`。模型按 `--model-cache` 指定路径缓存。

上述数据、具体核验结果、模型缓存清单、日志和实验记录均保留本地。交付代码可从接收方自己的 PDF 开始运行，不依赖开发者的解析记录。范围见 [提交说明](GITHUB_SUBMISSION.md)，操作见 [网页说明](WEB_USAGE.md)。

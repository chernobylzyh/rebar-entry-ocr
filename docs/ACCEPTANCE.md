# 接收方运行与核验

本文用于接收方在自己的环境和业务材料上核验交付代码。下列通过条件是待执行的要求，不代表接收方已经完成验证。运行代码与使用说明随仓库交付，业务 PDF、模型缓存、OCR 结果和实验资料需由接收方自行管理。

## 准备环境

准备 Python 3.10 或以上、JDK 17、Maven、Node.js 20.19 或以上及 npm；前端推荐 Node.js 24 LTS。WSL/Linux 中须使用 Linux JDK，设置正确的 `JAVA_HOME` 或将 `java`、`javac` 加入 `PATH`。

在独立 Python 环境中，从仓库根目录安装项目：

```bash
python -m pip install -e .
```

另行安装与运行设备兼容的 Paddle 计算后端。仅使用 CPU 时可执行 `python -m pip install paddlepaddle`；GPU 后端按设备与 CUDA 兼容条件准备。模型权重与缓存不随仓库分发，接收方需准备所需模型，或确保首次启动和识别时能够下载。缓存路径通过 `--model-cache` 指定。

## 启动三个服务

三个终端均从仓库根目录开始，保持服务运行。

```bash
# 终端一：激活已安装项目和 Paddle 的 Python 环境
python -m material_ocr serve --port 8000 --data-dir runs/web \
  --model-cache models/paddlex_cache
```

默认使用 `gpu:0`；CPU 环境在命令末尾增加 `--device cpu --profile complete`。

```bash
# 终端二：Java 业务服务，监听 8080
OCR_BASE_URL=http://127.0.0.1:8000 bash 前端/bin/start-local.sh
```

脚本启用 `application-local.yml`，自动建立文件型 H2 数据库，无需 MySQL。数据库保存在 `前端/runtime/h2/`，Java 文件数据保存在 `前端/image/`，日志位于 `前端/java/business/logs/run.log`。首次执行需要下载 Maven 依赖；已有缓存时可在命令末尾添加 `-o`。停止服务使用 `Ctrl+C`。

```bash
# 终端三：Vue 开发服务，默认监听 5173
cd 前端/vue
npm ci
npm run dev
```

依赖未变化时可跳过后续启动前的 `npm ci`。浏览器打开 Vite 实际输出的地址，默认是 `http://localhost:5173`。Vue 将 `/api` 和 `/image` 转发到 Java 的 8080，Java 再访问 Python 的 8000。可分别检查 Java 与前端代理：

```bash
curl http://127.0.0.1:8080/api/ping
curl http://127.0.0.1:5173/api/ping
```

两者应返回包含 `"code":200` 的 JSON。仅页面可打开不代表 OCR 链路已可用；模型依赖与 Python 服务仍需准备完成。MySQL 部署方式及构建命令见[仓库 README](../README.md)。

## 核验自己的业务材料

使用接收方有权处理的 PDF，尽量覆盖报审表、进场数量清单、质量证明书、铭牌和送货单。上传后执行整卷识别，检查自动提取、四表关联和最终台账；匹配阶段无需人工捆绑候选。

| 核验项 | 操作与通过条件 |
| --- | --- |
| 上传与服务链路 | 上传后能够查看卷名、页数和原图；处理完成，或明确显示失败原因。 |
| 自动匹配 | 整卷识别后生成台账；按原图核对清单、质证、铭牌、送货来源的关联，重复记录不造成数量重复累计。 |
| 诊断与来源 | 缺失、识别不清、冲突和多候选具有原因；点击字段或诊断页码可查看对应原图和定位证据。 |
| 最终补正 | 双击单元格修改字段；人工补正与原始 OCR 观察能够区分，补正不伪装成 OCR 命中。 |
| 核验约束 | 未核验的台账不能导出；缺少必填字段或验收数量不是大于零的吨数时不能完成核验。 |
| 确认失效 | 完成「核验关键字段」后修改字段或重新识别，旧确认失效，须重新核验。 |
| Excel | 核验后导出，检查「台账」和「字段溯源」两张工作表；字段值、单位、页码与页面一致。 |
| 数据持久化 | 刷新页面及正常重启 Java 后，自己的历史记录和已保存内容仍可读取。 |

台账包含以下 12 个业务字段，PDF 标识用于来源展示：供应商是否报审、文件编号、材料名称、规格品种、生产单位、供应单位、供货日期与工程材料报审签认日期、使用部位、送货单编号、炉批号、验收数量、质保书编号。数量单位为吨；「供应商是否报审」「文件编号」「送货单编号」没有可靠来源时按界面诊断处理，不为导出而猜值。

接收方应逐项标明通过、失败或未覆盖。样本不包含冲突、重复或多候选等情况时，对应项目记为未覆盖；单一样本通过不能代替总体准确性评价。

## 反馈与数据管理

问题反馈应包含代码版本、运行环境、设备模式、操作步骤、错误提示与相关日志。需要指出业务错误时，提供有权限共享的页码、字段原文、预期值及必要证据；输入与导出文件由接收方自行保管。

Python 数据目录为启动时指定的 `runs/web/`；Java 文件数据位于 `前端/image/`，历史数据库位于 `前端/runtime/h2/`。备份或迁移时一并保留相关数据，复制 H2 文件前先停止 Java。业务扫描件、模型缓存、处理结果及核验资料不提交代码仓库。
